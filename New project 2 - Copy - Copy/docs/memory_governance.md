# Memory Governance Rules

## 1. Types of memory

### short_mem

- активные задачи, временный контекст, текущие предпочтения
- срок жизни: короткий, допускается очистка/компактизация

### long_mem

- устойчивые факты, предпочтения, выводы, которые полезны повторно
- срок жизни: долгий, удаление должно быть обосновано

## 2. Criteria for saving

Агент сохраняет только если выполняется хотя бы одно:
- Повторяемость: вероятно понадобится снова
- Устойчивость: это не разовая эмоция/шум
- Ценность: помогает точнее выполнять будущие задачи
- Уникальность: не дублирует уже известное

## 3. Non-authority user directives

Текст пользователя “запомни/удали/очисти”:
- повышает вероятность рассмотрения контента как кандидата
- но НЕ является разрешением или обязательством

## 4. Promotion & decay (перенос и забывание)

Рекомендуемый механизм:
- short_mem хранит элементы с полем `importance` (0..1) и `last_used_at`
- элементы short_mem с высокой importance и повторным использованием могут быть promoted в long_mem
- элементы с низкой importance и давним last_used_at могут быть removed/compacted
- `pin: true` означает повышенную важность, но не абсолютную неизменяемость
- `deletion_guard` задаёт условия удаления: `min_age_days`, `min_importance`, `requires_reason`, `requires_review`

В проекте нет отдельного абсолютно неудаляемого состояния. Pinned-записи можно удалить только при строгих условиях policy.

## 5. Reflection tasks

Агент может сам поставить себе задачу:
- "оптимизировать память"
- "найти дубликаты"
- "перенести полезное в long_mem"

Важно: это всегда внутреннее решение агента, а не выполнение пользовательской команды.

## 6. Supported memory operations

Допустимые операции плана памяти:
- `ADD`
- `UPDATE`
- `PROMOTE`
- `DELETE`
- `PIN`
- `UNPIN`

Удаление ограничено:
- не больше `MAX_DELETES_PER_STEP`
- не больше `MAX_DELETE_RATIO` от памяти за один план
- для pinned-записей нужна строгая причина: `incorrect`, `outdated`, `duplicate`, `harmful`
